# --- Thunar / xfdesktop right-click menu dependency, declared explicitly ---
# Added 2026-08-26 by <agent>. This edition is the ONLY one that ships

# WHY DECLARE IT AT ALL, given it currently arrives transitively: thunar-uca
# builds {"/bin/sh","-c",<expanded>,NULL} and DISCARDS THE CHILD'S STDERR, so a
# missing binary is not an error message, it is total silence. The user clicks

# happened on a shipped image.

# exiftool, behind three menu entries: "Kodachi Strip Image Metadata",
# "Kodachi Strip PDF Metadata" and "Kodachi View Metadata".
#
# MEASURED over the true merged gui-xfce population (common + terminal +
# gui-xfce = 1930 lines): xclip, gtkhash, firejail, mat2, zenity, catfish and
# podman are ALREADY declared and need nothing. libimage-exiftool-perl was the
# only command behind a menu entry that no list DECLARES.
#
# CORRECTION, 2026-08-26, measured on the built system rather than on the lists.
# The line above answers "is it declared?" and an earlier version of this comment
# presented it as "is it available?", which is a different question and the wrong
# one. It was NEVER missing from the image. On <lab-host>, built before this
# line existed:
#     dpkg -S /usr/bin/exiftool        -> libimage-exiftool-perl
#     apt-mark showauto                -> libimage-exiftool-perl  (AUTO)
#     apt-cache rdepends --installed   -> mat2
# mat2 is declared, and it pulls exiftool in transitively. So the three metadata
# entries were working, and this line is HARDENING, not a bug fix: it converts a
# transitive dependency into a declared one so those entries stop depending on
# mat2's dependency graph staying as it is.
#
# exo-utils is in the IDENTICAL position (AUTO, undeclared, present, providing
# exo-open behind two entries) and is deliberately NOT added here: it arrives
# with the XFCE stack, which is definitionally present on a gui-xfce image,
# whereas mat2 is a single removable privacy tool. Naming it so the next reader
# does not have to re-derive the difference.
